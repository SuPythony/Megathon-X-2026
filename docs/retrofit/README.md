# Retrofit engine (Part 2): what it does and where

Implements `EnergyRetrofitEngine` (`greentwin/interfaces.py`) as `greentwin.retrofit.engine.RetrofitEngine`, and the orchestrator's `run_scenario` that joins it to the twin, score, value and feasibility. Design: `LLD.pdf` §4.2. Decisions, proofs and the worked example: `docs/retrofit/DECISIONS.md`.

Numbers come from P2's physics (`physics_l1`) on each home's calibrated posterior (SVI on its meter readings). Provenance is `mock` only if the stand-in physics is loaded; `mock` results never reach the demo or the disk cache.

| Module | What it does |
| --- | --- |
| `retrofit/catalogue.py` | Validated catalogue, fabric-first ordering, alternatives, sampled costs (null + reason when unsourced), confirmed grants only |
| `retrofit/rules.py` | Feasibility layer 1 (`feasibility_rules.json`); rule vetoes always win |
| `retrofit/runner.py` | Batched twin runs per package (never summed) via the twin's `simulate`, meter anchoring, bills (Ofgem Q4 2026), carbon (DESNZ 2025), `EnergyBreakdown` |
| `retrofit/property_edits.py` | `property_after`: the recorded features after a package, for the projected score |
| `retrofit/rating.py` | `sap_estimator.json`: standard-mode runs → anchored SAP → `RatingEstimate` ("estimated rating, not an EPC") |
| `retrofit/ladder.py` | Selection, order, per-fuel marginal effects per sample, cost, payback, p_net_benefit, p_suitable, p_gain, verdict, reason, projected score |
| `retrofit/potential.py` | Improvement potential: all feasible retrofits in ONE run; null + reason at baseline 0; with surveys |
| `retrofit/engine.py` | `RetrofitEngine`: the Protocol, per-home warnings, provenance |
| `optimise/pareto.py` | ≤ 256 packages, P(on front) per sample, knee per goal, budget filter; reference-point mode, memory re-rank, greedy and CO2-only baselines, hypervolume |
| `optimise/staging.py` | Stages the ladder over years by dependencies and cash flow (exact DP, R-22) |
| `models/relevance.py` | P(an EPC assessor would recommend X): one EBM per measure on real EPC recommendations; rules baseline (R-26) |
| `api/orchestrator.py` | `run_scenario(ScenarioSpec) → ScenarioResult` and `plan()`; cached in memory and `cache/scenarios` (R-27) |

## Where it is used
| Caller | Entry point |
| --- | --- |
| API | `POST /api/scenario` (ScenarioSpec → ScenarioResult), `GET /api/plan/{pid}?goal=&budget_gbp=&annual_budget_gbp=&min_carbon_kg=&max_cost_gbp=&customer_id=` |
| LLM chat | tool `run_scenario` (`greentwin/llm/tools.py`): every what-if reruns the twin; returns only tool numbers |
| Batch | `scripts/retrofit_showcase.py`, `scripts/eval_retrofit_ranking.py` |

```bash
uv run pytest -q tests/test_retrofit_catalogue.py tests/test_retrofit_engine.py tests/test_retrofit_plan.py
uv run python scripts/retrofit_showcase.py          # SH1-SH3 -> artifacts/retrofit/v1/*.json (calibrated posteriors)
uv run python scripts/eval_retrofit_ranking.py      # ranking vs generator-rule labels -> eval/reports/retrofit_ranking/
uv run python scripts/epc_recs_extract.py --year 2025 --permille 20 && uv run python scripts/train_relevance.py
uv run uvicorn greentwin.api.app:app --port 8050    # then POST /api/scenario, GET /api/plan/SH2
```
